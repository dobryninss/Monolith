# Спасательная капсула 6×6

[Рецепт](rescue_capsule.json) воспроизводит [готовую карту](../../../../Resources/Maps/_Exodus/Shuttles/rescue_capsule.yml) обычного формата Grid. Сохранение остаётся до MapInit. В карте используются существующие прототипы; новых игровых систем и записей в продаже шаттлов нет.

Капсула рассчитана на двух человек. Внешний размер — 6×6 тайлов. Установлены разблокированная консоль управления, два кресла, четыре малых двигателя, гироскоп, гравитация, освещение, стыковочная дверь и воздушная завеса. Питание: настенный APU → HV → подстанция → MV → APC → LV. Баллон восполняет воздух, переносной скруббер забирает CO₂ из соседних клеток обоих кресел. Начальная атмосфера: 101,325 кПа, 293,15 K, кислород/азот 21/79.

Для загрузки рабочей копии на dev-сервере:

```text
mapping 100 /Maps/_Exodus/Shuttles/rescue_capsule.yml true
```

Для тестирования этой копии выполните `mapinit 100`, пристегнитесь к креслу возле консоли и откройте консоль. Это инициализирует игровую копию; редактируемым источником остаётся исходный YAML. Для новых правок загрузите его заново либо используйте сессию инструмента.

## Выполненные проверки

Проверенная ревизия YAML: `24772c6d8b93e8c6d024dca0417a43c5a49d5c75a5d7ed6711a033fc440c4580` (SHA-256).

- 63 Python-теста прошли: кодек, сохранность данных, операции, конфликты, восстановление экспорта, каталог, схема, воздух и совпадение экспортированной карты с рецептом.
- Существующий `Content.Server.dll` загрузил и сохранил капсулу, затем другой процесс повторно загрузил результат и симулировал 60 секунд. Ошибок загрузки/сериализации не было, исходник не изменился. Все 13 заданных клеток сохранили 101,325 кПа и 293,15 K.
- Отдельно проверена ветка `Map`: `loadmap → savemap → отдельный процесс → loadmap → mapinit → savemap`.
- Сценарий с двумя `MobHuman` подтвердил пристёгивание, штатный допуск пилота через консоль, питание всех 10 потребителей до и после 60 секунд и отсутствие удушья. Скруббер собрал около 0,126 моль CO₂. Тяга доступна во всех четырёх направлениях, гироскоп активен.

Сценарии используют уже собранный сервер. Сборка игры не запускалась. Ввод клавиш движения, вращение, торможение, FTL и открытие внешней двери этим консольным сценарием не проверены. `Pilot.HeldButtons` недоступен для записи через существующий VV API.

Добавлен [C# интеграционный тест](../../../../Content.IntegrationTests/Tests/_Exodus/Mapping/RescueCapsuleTest.cs) `CapsuleSurvivesSaveLoadAndSupportsFlightAndBreathing`: он также проверяет движение в четырёх направлениях, вращение, торможение и дыхание при открытой двери. Он **не собирался и не запускался**. Короткая проверка капсулы не является нагрузочным тестом сервера.

## Воспроизведение

Из корня репозитория, после установки зависимостей из [requirements.txt](../requirements.txt):

```powershell
py -3 -m unittest discover -s Tools/_Exodus/Mapping/tests
py -3 Tools/_Exodus/Mapping/mapping.py validate-file Resources/Maps/_Exodus/Shuttles/rescue_capsule.yml --requirements Tools/_Exodus/Mapping/examples/rescue_capsule.json
py -3 Tools/_Exodus/Mapping/mapping.py engine-check Resources/Maps/_Exodus/Shuttles/rescue_capsule.yml --output artifacts/_Exodus/Mapping/capsule-check-new --seconds 60 --requirements Tools/_Exodus/Mapping/examples/rescue_capsule.json
py -3 Tools/_Exodus/Mapping/tests/capsule_smoke.py Resources/Maps/_Exodus/Shuttles/rescue_capsule.yml --output artifacts/_Exodus/Mapping/capsule-occupants-new --seconds 60
```

Для каждого запуска сервера нужен новый каталог вывода. `engine-check` сохраняет `report.json`, а сценарий с людьми — `smoke-report.json`. В обоих случаях рядом находится серверный лог. Полный рабочий цикл агента описан в [README](../README.md).
